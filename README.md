# Engine2D: лабораторная работа 1

Локальная ветка для доработок: `semen`, создана от `main`.

## Проверка заданий

Сверка выполнена по разделу 3 инструкции `gk-lab01.pdf`, страницы 3-4.
В этой лабораторной нужны каркас 2D-движка и перечисленные функции `Engine`.
Управление игровыми объектами, физика, звук, singleton и observer описаны во
введении, но не являются отдельными обязательными заданиями раздела 3.

| Пункт | До доработки | Сейчас |
| --- | --- | --- |
| Каркас проекта 2D | C++, CMake, SDL3, отдельные модули | Есть |
| Инициализация графической библиотеки | SDL, окно, renderer | Есть; ошибка на любом этапе освобождает ресурсы |
| Окно / полный экран / разрешение | Параметры `Initialize` | Есть; доступны также через аргументы запуска |
| Настройка FPS и включение ввода | FPS был; переключателей ввода не было | FPS, клавиатура и мышь настраиваются отдельно |
| Главная петля с таймером | Была | Есть; таймер сбрасывается перед запуском, лимит FPS учитывает доли миллисекунды |
| Клавиатура и мышь | События сохранялись внутри приватного `Input` | Состояние доступно через `Engine::GetInput`; исправлены колесо и потеря фокуса |
| Очистка экрана заданным цветом | Была, цвет в `Render` фиксирован | `ClearScreen` проверяет результат; `SetClearColor` задаёт цвет для последующих кадров |

| Завершение и освобождение ресурсов | Основное завершение было | Повторный `Shutdown` безопасен; неудачная инициализация также очищает ресурсы |

сохранены для дальнейших лабораторных.

## Запуск в CLion

1. Открыть корневую папку как CMake-проект.
2. В **Settings → Build, Execution, Deployment → Toolchains** выбрать
   **Bundled MinGW** и CMake версии не ниже 4.0.
3. В настройках **CMake** выбрать этот toolchain, затем перезагрузить CMake-проект.
4. Выбрать конфигурацию **Engine2D** и нажать Run (`Shift+F10`).

Нужны Git и интернет для первоначальной загрузки SDL3. SDL3 скачивает CMake;
отдельно устанавливать SDL не требуется.

По умолчанию: окно 1280×720, 60 FPS, клавиатура и мышь включены.
В **Run → Edit Configurations → Program arguments** можно указать:

```text
--width 800 --height 600 --fps 30
```

Другие параметры: `--fullscreen`, `--no-keyboard`, `--no-mouse`, `--help`.
Ширина, высота и FPS должны быть положительными целыми числами.

## Проверка вручную

- Удерживать R, G или B: фон становится красным, зелёным или синим.
- Удерживать левую / правую кнопку мыши: фон становится жёлтым / голубым.
- Крутить колесо при удержании клавиши цвета или кнопки: меняется яркость.
- Отпустить клавиши и кнопки: возвращается серый фон.
- Переключиться на другое окно: нажатые клавиши сбрасываются.
- Escape или закрытие окна: завершение программы.
- С `--no-keyboard` клавиши игнорируются; с `--no-mouse` мышь игнорируется.
  Закрытие окна работает в обоих случаях.

`logs.txt` создаётся в рабочем каталоге запуска и исключён из Git.

## Автоматическая проверка

Сборка цели `engine_tests`, затем запуск CTest из каталога сборки:

```powershell
ctest --test-dir cmake-build-debug --output-on-failure
```

Тесты используют виртуальный видео-драйвер SDL: проверяют состояния ввода,
колесо по кадрам, отключение устройств, потерю фокуса, таймер, лимит FPS,
валидацию параметров, запуск петли, выход, повторную инициализацию, освобождение
SDL и диагностический файл. Отдельно проверяются `--help` и отклонение FPS = 0.

## Работа с командой

Все доработки следует коммитить в `semen`. Перед коммитом проверить `git status`.
Не добавлять каталоги сборки, `.idea` и логи.

```powershell
git branch --show-current
git add .gitignore CMakeLists.txt engine.cpp engine.h input.cpp input.h logs.cpp main.cpp timer.cpp timer.h README.md tests/engine_tests.cpp
git commit -m "Complete lab 01 engine configuration and input handling"
git push -u origin semen
```

После push открыть pull request из `semen` в `main`, чтобы команда могла
проверить изменения перед объединением.
